## Executive Summary & Root Cause Verdict

### High-Level Verdict: **Combination of (a) and (b)**
1. **Never Emitted on CLI Headless Stream (`--output-format stream-json`): (a)**
   When the Antigravity CLI (`agy`) is run in headless non-interactive batch/turn mode with `--input-format stream-json --output-format stream-json -p ""`, the underlying engine (`agy`/`cortex`) **never emits thinking/reasoning text deltas into stdout**.
   - `agy` records thinking tokens numerically in usage telemetry (`usage.thinking_tokens`), and stores full model thinking text internally in its internal brain transcript logs (`.system_generated/logs/transcript_full.jsonl` under the property `"thinking"` on `PLANNER_RESPONSE` steps).
   - However, in the public stream-json protocol emitted to stdout, `agy` emits only `step_update` events for `step_type: "agent_response"` (containing `text_delta` for user-visible response text or usage counts), `step_type: "tool"`, `step_type: "error_message"`, `step_type: "system_message"`, and `step_type: "checkpoint"`. **No thought text stream events or thought fields are emitted on stdout.**

2. **Parser/Normalizer Specification & Blind Spot: (b)**
   In `src/agent_bridge/adapters/antigravity.py` (`classify_event` L378–L381):
   - The adapter was designed with speculative heuristics:
     ```python
     if step_type == "checkpoint" or event in {"thought", "reasoning"}:
         text = _first_text(step, obj, keys=("text", "text_delta", "thought", "reasoning", "summary"))
         return ("thought_chunk", {"text": text}) if text else ("raw", {})
     ```
   - In actual `agy` executions, `step_type: "checkpoint"` events do occur (e.g. during context compaction / resume), but they carry only `{"conversation_id": "...", "step_index": N, "state": "DONE", "step_type": "checkpoint", "duration_seconds": ...}` without any `text` or `thought` payload. Consequently, `classify_event` returns `("raw", {})`, which is deliberately ignored by the dashboard feed.
   - If `agy` were ever invoked with or updated to emit thought deltas (such as `step_type: "thought"` or `step_update.thought` / `step_update.reasoning`), the adapter would theoretically map them if the keys match, but currently `agy` CLI's `stream-json` produces 0 thought chunks.

3. **Dashboard & Downstream Pipeline Status: Ready and Fully Functional: (NOT c)**
   Thinking blocks are **not** missing due to dashboard rendering failure:
   - The dashboard ingestion (`dashboard_events.py:normalize_event`) fully supports `"thought_chunk"` -> `{"t": "think", "ts": ts, "text": text}`.
   - The web UI (`dashboard_page.py`) implements `<details class="block think">` with CJK character / English word count badges, sparkle icons, live streaming expansion, and Markdown export (`<details><summary>Thinking</summary>...</details>`).
   - The reason thinking blocks are not visible in the dashboard for Antigravity sessions is strictly upstream: **zero `thought_chunk` records are ever persisted in Antigravity transcripts**.

1. `event: "init"`: Initial session state (`cwd`, tools list, permission mode).

3. `event: "result"`: Final payload with `status` (`SUCCESS` / `ERROR`), `response` (matching joined `text_delta` values), `usage`, and `conversation_id`.

## 2. Answers to Specific Questions

### Question 1: What exact Antigravity stream event/schema represents thinking/reasoning?
- In `agy`'s internal brain transcript (`transcript_full.jsonl`), reasoning is stored in the `"thinking"` string field of `type: "PLANNER_RESPONSE"` objects.
- In `agy` CLI's public `stream-json` standard output, **there is currently no stream event or field representing thinking text**.
- `agy` only surfaces `usage.thinking_tokens` (an integer token count) in `step_update.usage` and `result.usage`.
- If `agy`'s CLI were updated to expose thought deltas over `stream-json`, it would either be a dedicated `step_type` (e.g., `step_type: "thought"` or `"reasoning"`) with a `thought` / `text_delta` field, or an event type `event: "thought"` with a delta string.

### Question 2: Which source files and symbols parse and normalize it?
- **CLI Adapter parsing:** [`src/agent_bridge/adapters/antigravity.py`](file:///C:/Users/Touma/Documents/Agent-Bridge/src/agent_bridge/adapters/antigravity.py):

- **Dashboard ingestion normalization:** [`src/agent_bridge/share/dashboard_events.py`](file:///C:/Users/Touma/Documents/Agent-Bridge/src/agent_bridge/share/dashboard_events.py):

### Question 7: Edge cases to handle
1. **Streaming deltas vs. full blocks:** `addThink` in `dashboard_page.py` concatenates chunks into `curThink._text += e.text`. If `agy` were to emit full thought snapshots rather than deltas, concatenation would duplicate text unless tagged or diffed.
2. **Interleaving with Tool Calls:** In `dashboard_page.py` (L1584), receiving a tool call closes open think blocks (`curThink = null`). A model that thinks, executes a tool, and thinks again correctly opens two sequential `<details class="block think">` folds.
3. **Empty or Whitespace-only Thought Events:** `dashboard_events.py` (L141) explicitly drops empty thought chunks (`if not text: return None`). If an adapter emits an empty thought step, it correctly becomes a no-op.
4. **Usage-only completion steps:** `step_type: "agent_response"` with `state: "DONE"` often has no text. The adapter must not classify these as empty thoughts.
5. **Backwards Compatibility:** Legacy transcripts already on disk contain `{"payload": ...}`. `normalize_event` must preserve existing behavior for non-thought records.
